# 建 Wiki 前的需求摘要

## 作業指定

主題可自行選擇。先討論範圍，再建立 Wiki，納入至少五篇資料。以 Wiki 做一份零基礎讀者可使用的 HTML 簡報，交付流程、一次實跑的檢查紀錄和反思。

## 建檔前提出的設計

- 範圍與讀者。以 HTTP 快取為主題，面向初次接觸 HTTP 的同學。用一張社團海報貫穿，將瀏覽器的快取行為拆成直接重用、驗證與取得新版。
- 頁面與語言。繁體中文的概念頁、來源摘要、索引與日誌。HTTP 標頭、指令及狀態碼保留英文原文。
- 引用。每個概念的說法連到來源頁內對應段落，簡報再連到該說法。RFC 確定規範語義，MDN 支援可理解的範例，Chrome 官方資料支援工具操作。
- 分歧處理。看似衝突時先縮小情境。例：一般再次請求和瀏覽器手動重新整理可能走不同路徑。
- Ingest。五篇依序處理，各自保存擷取記錄與來源摘要，然後彙整交叉連結。
- 產出與驗收。離線 HTML、逐頁引用、圖解、練習與檢查紀錄。自動檢查資料結構、引用與兩個已知條件，並做 Chrome 瀏覽測試。

## 實際對話與確認順序

1. 作業原始請求：「主題可以自行選擇」「使用『先討論、後生成』的方式建立 Wiki」「至少 ingest 5 篇資料」。
2. Codex 在初版建檔前提問：

   > 建 Wiki 前，我建議用「HTTP 快取入門」，對象是沒學過 HTTP 的同學。範例會追蹤同一張圖片的請求，另比較三種 Cache-Control 指令。你想採用這個範圍，還是調整主題或讀者？

3. 初版依自由選題授權執行，當時範圍問題尚未收到答覆。初版交付後，使用者回覆：「採用這個範圍」。
4. 使用者接著要求公開網址、重跑日期與來源擷取、補實際對話及瀏覽器截圖。
5. 本次以第 3 步已確認的主題、讀者和案例，重新取得五篇來源、更新 Wiki，再檢查並產生 HTML。擷取與瀏覽器 JSON 檔保存此次實際時間。

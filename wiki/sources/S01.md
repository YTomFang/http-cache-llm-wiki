# S01 · RFC 9111 · HTTP Caching

規範 HTTP 快取的儲存、重用、期限及驗證。以它確認規則與適用條件。

[擷取紀錄](../../raw/S01.md) · [原文](https://www.rfc-editor.org/rfc/rfc9111.html)

<a id="section-3"></a>
## §3 Storing Responses in Caches

回應要符合儲存條件才可保留。儲存和之後是否能重用是兩個判斷。

[查閱原文段落](https://www.rfc-editor.org/rfc/rfc9111.html#section-3)

<a id="section-4.2"></a>
## §4.2 Freshness

當 freshness lifetime 大於 current age，回應為 fresh。兩者相等時已達期限。

[查閱原文段落](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2)

<a id="section-4.3"></a>
## §4.3 Validation

快取不能直接重用時，可利用條件式請求驗證已儲存的回應。

[查閱原文段落](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.3)

<a id="section-5.2.2.1"></a>
## §5.2.2.1 max-age

回應指令的秒數用來判斷 freshness lifetime。

[查閱原文段落](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.1)

<a id="section-5.2.2.4"></a>
## §5.2.2.4 no-cache

無參數的指令要求重用前向來源驗證並取得成功回應。

[查閱原文段落](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.4)

<a id="section-5.2.2.5"></a>
## §5.2.2.5 no-store

收到此回應指令的 HTTP 快取不得儲存這次回應。

[查閱原文段落](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.5)

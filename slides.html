條件式請求

到期後，先確認版本

若過期副本附有 ETag: "poster-v1"，瀏覽器可在條件式 GET 的 If-None-Match 帶上這個舊標記。

GET /poster.png
If-None-Match: "poster-v1"

標記相符

304 Not Modified

回應有標頭、無圖片內容。瀏覽器使用舊副本。

標記不同

200 OK + 新海報

請求成功時，伺服器傳回新版圖片。

快取指令

三種 Cache-Control 指令

看的是伺服器回應標頭。先區分「可否儲存」與「何時能重用」。

max-age=60符合條件可存新鮮期限為 60 秒。符合重用條件時可直接使用。
no-cache符合條件可存每次重用前都要成功驗證。
no-store不得儲存此單一指令情境下，HTTP 快取不得保留這次回應。

動手觀察

在 Network 找到快取線索

在 Chrome 開發者工具觀察同一個圖片網址。選一張帶快取標頭的圖片，從不同頁面再次載入。

  1. 記住請求

    勾選 Preserve log。觀察正常快取時，讓 Disable cache 維持未勾選。

  2. 打開 Headers

    在 Response Headers 找 Cache-Control 和 ETag，再到 Request Headers 找 If-None-Match。

  3. 讀結果

    看到 304 代表這次有網路驗證，瀏覽器可沿用舊副本。

回顧

再請求時，問這三件事

下次在 Network 看到快取相關的回應，可以用這三個問題判讀。

  1. 有符合儲存條件的副本嗎？

    沒有可用副本時，通常要請求完整資源。

  2. 可以直接重用嗎？

    可用且仍新鮮的副本可直接使用。

  3. 需要驗證嗎？

    有 ETag 時可送條件式 GET。標記相符回 304，標記不同且成功取得資源時回 200 和新內容。
